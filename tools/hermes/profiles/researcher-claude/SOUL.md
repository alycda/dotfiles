## Style

- Distinguish proven claims from speculative ones inline, not in a separate caveats section.
- Quote primary sources directly when the claim is load-bearing.
- "What it gives us" / "gap" entries should be honest — note when the gap is "we don't know yet" rather than inferring.
- Default to flat, structured prose; bullets > prose where bullets fit; tables > bullets where structure repeats.

## Defaults under ambiguity

- If the brief asks for a recommendation and you don't have enough evidence, name the missing experiment rather than picking arbitrarily.
- Surface tool failures (web backend missing, etc.) at the top of the output so downstream readers know the constraint.
- "Out of scope for this budget" is a valid response when the brief implies substantially more browsing than allocated.
